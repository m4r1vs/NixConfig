## Repository Overview

Multi-platform Nix flake configuring NixOS, nix-darwin, and WSL hosts with home-manager. Stable nixpkgs (`nixos-26.05`) is the base; selected packages come from unstable or overlays.

## Commands

- `rebuild` — script in PATH on every host; runs `sudo nixos-rebuild switch` or `sudo darwin-rebuild switch` for the current host and re-applies the active specialisation (read from `/etc/nixos_active_specialisation`).
- `sudo nixos-rebuild switch --flake ~/NixConfig/#<host>` — manual equivalent.
- `nixos-rebuild build --flake .#<host>` — build without switching (useful to verify a config change evaluates and compiles).
- `nix build .#bootstrap_local_x86_64` / `.#bootstrap_remote_arm64` — build install ISOs.
- Format Nix files with `alejandra` (the formatter used throughout this repo).

## Architecture

### systemArgs threading

Every host in `flake.nix` defines a `systemArgs` attrset (username, git identity, hostname, `theme` from `makeTheme.nix`, platform, and for servers ipv4/domain). It is injected via `config._module.args` and is available as the `systemArgs` argument in **every** NixOS, darwin, and home-manager module. Platform checks like `isDarwin = systemArgs.system == "aarch64-darwin"` are the standard pattern.

### Auto-imported modules + `configured.*` enable options

`nixos-modules/default.nix` and `home-manager/modules/default.nix` automatically import every sibling `.nix` file and every subdirectory (its `default.nix`). Consequences when adding a module:

1. Create the file — **no import registration needed**.
2. The module **must** gate its config behind a `mkEnableOption` (`options.configured.*`, `options.programs.configured.*`, or `options.services.configured.*`) with `config = mkIf cfg.enable {...}`. Without this it applies unconditionally to all hosts.
3. Enable it per-host in `hosts/<host>/default.nix` (NixOS options) or in `home-manager/home.nix` (home-manager options, typically keyed off `isDesktop` / `isDarwin` / `isWSL`).

### Scripts system

`home-manager/scripts/*.nix` each export an attrset of `pkgs.writeShellScript` derivations. `home-manager/makeScripts.nix` auto-collects all of them and passes the merged set as the `scripts` argument to every home-manager module (via `extraSpecialArgs`). Reference a script as `${scripts.<name>}`; scripts can reference each other through the same `scripts` argument.

### Hosts (`flake.nix` + `hosts/`)

- `worknix`, `nixpad`, `desknix` — graphical x86 workstations (Hyprland).
- `nixner` — aarch64 Hetzner server (comin GitOps, homepage, binary cache, DNS; server services live in `nixos-modules/server/`).
- `kubenix` — Kubernetes node fleet, generated by `hosts/kubenix/default.nix`.
- `winix` — NixOS on WSL. `nixbook` — macOS via nix-darwin (`hosts/darwin/`). `yannix` — machine for a different user.
- `hosts/nixos.nix` is shared by all NixOS hosts; `hosts/default.nix` + `nixpkgs.nix` are shared by everything including darwin.

### Desktop specialisations

`nixos-modules/desktop.nix` defines `configured.desktop.windowManagers.{hyprland,i3,gamescope}` as NixOS specialisations with one marked default. The `rebuild` script keeps the active specialisation across rebuilds.

### Overlays and unstable packages

All overlays live in `nixpkgs.nix`: own flake-input packages (atai, golazo, …), custom font derivations from `assets/fonts/`, and packages pulled from `nixpkgs_unstable` via `pkgsUnstable`. Prefer adding version overrides there rather than in individual modules.

### Theming

`makeTheme.nix` maps primary/secondary color names to hex/RGB; each host picks its pair in `flake.nix` and modules read colors from `systemArgs.theme`. Runtime palette switching (dark/light, per-wallpaper) is handled by the `custom-wallpaper-theme` script writing `~/.theme/palette.json`.

### NeoVim

Plugins are managed by lazy.nvim, not nixpkgs; the lazy lockfile is tracked in `home-manager/modules/neovim/nvim/` so plugin updates show up in git.
